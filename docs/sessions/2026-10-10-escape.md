# 2026-10-10 - Escape lets go of everything (both apps)

## Asked

"When pressing Escape ... it should clear the selection from the timeline
AND the instrument", so an idea can be inserted onto every instrument at
once. Asked where a single melody should go with no instrument chosen, the
user chose **the top instrument only** over sharing it with every part.

## Built (0048)

- `Controller::letGoOfEverything`, the same in both apps: stops playing and
  step/note input, clears the selection and the chosen bars, and sets
  `noPartChosen`. Escape calls it and nothing else; it used to do one of
  stop, end input, or clear the notes.
- `lineTarget` gives the top part while `noPartChosen`; `place` needed no
  other change, since "nothing chosen" already shared chords across every
  part (0041). `insertGenerated` leaves the flag alone, so idea after idea
  goes to every part.
- Choosing a part ends it: `choosePart`, `caretToPart`, `selectRange`,
  drawing or writing a note, a note clicked (Miderator's roll, Noterator's
  page and lasso), `addPart`, a new or opened score. `setCaret` alone does
  not, because the ruler moves the caret with the caret's own part, and
  moving where an idea starts should not choose an instrument.
- Nothing marked while no part is chosen: the track header and the roll's
  name (Miderator), the staff's side mark (Noterator), the Parts tab's row.
  Noterator's caret runs down every staff. The status line says "no part
  chosen" / "Every part, bar 3 beat 2"; the Generate tab's "Into" line was
  already right, as it reads `lineTarget`.
- A test in both `TestApp.cpp`s, failing on the old `lineTarget` (the
  melody went to the viola, not Violin I).
- The keys help (H) and the READMEs say what Esc does.

No shared file changed (`docs/SHARED.md`): the controller, the views and the
panels are each app's own, and `GeneratorPanel.*` already asked the
controller.

## What looked broken and was not

- Escape reaches the window even with the Generate tab's results list
  focused - checked headless, the list does not take the key.
- The `-Wshadow` warning for `roots` in `ScaleModel.h` is ScaleView's file,
  there before this session; it is never edited here.
